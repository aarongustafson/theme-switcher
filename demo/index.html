<theme-switcher>

Choose System, Light, or Dark using native radios. See the README for installation and the API.

All controls on this page share its theme and use the demo-only storage key theme-switcher-demo. The Sepia example has its own document so it can use a different set of choices.

Use Tab to reach a group, arrow keys to move between choices, and Space to select. Only System follows changes to your device’s color preference.

Start with three choices

Configure the control with attributes

The component supplies a named radio group and its default styles. It sets data-theme on <html>; the page’s CSS supplies the colors. An explicit choice stays put when your device switches modes. 

<theme-switcher
  label="Color theme"
  storage-key="theme-switcher-demo"
></theme-switcher>

/* Your page styles */
:root { color-scheme: light dark; }
:root[data-theme='light'] {
  color-scheme: light;
}
:root[data-theme='dark'] {
  color-scheme: dark;
}
Waiting for the component.

Reload to try restoring the saved choice.

Keep your markup and form behavior

Enhance an authored fieldset

The legend and labels name the controls, and the checked radio establishes the reset default. These controls still work without JavaScript. Conflicting host configuration doesn’t replace authored choices, names, labels, or values. 

<form>
  <theme-switcher
    storage-key="theme-switcher-demo">
    <fieldset>
      <legend>Reading appearance</legend>
      <label><input type="radio"
        name="appearance" value="system"
        checked>Use my device</label>
      <label><input type="radio"
        name="appearance"
        value="light">Light</label>
      <label><input type="radio"
        name="appearance"
        value="dark">Dark</label>
    </fieldset>
  </theme-switcher>
  <button>Inspect FormData</button>
  <button type="reset">Reset</button>
</form>

Make it fit your site

Restyle the segments

The same --multi-switch-* properties work here as in <form-multi-switch>. Default styles live in a cascade layer, so your CSS can override them. 

<theme-switcher class="pill"
  label="Site appearance">
</theme-switcher>

.pill {
  --multi-switch-radius: 999px;
  --multi-switch-border: #173f63;
  --multi-switch-background: #eef4ff;
  --multi-switch-color: #173f63;
  --multi-switch-selected-background: #173f63;
  --multi-switch-selected-color: #fff;
}

The border joins remain connected, including at narrow widths.

Add icons without losing the labels

CSS masks add decorative icons. The text still names each radio. Add icon-only to hide that text visually, not from assistive technology. The icon-only example also uses the hide-legend CSS class from the README to hide its legend visually while keeping the group named. 

<theme-switcher class="icons"
  label="Icons and text">
</theme-switcher>
<theme-switcher class="icons hide-legend" icon-only
  label="Icon-only appearance">
</theme-switcher>

.icons [data-multi-switch-choice]::before {
  content: '';
  inline-size: 1.25em;
  block-size: 1.25em;
  background: currentColor;
  mask: var(--theme-icon) center / contain
    no-repeat;
}
.icons [data-value='dark'] {
  --theme-icon: url('./dark.svg');
}
/* Add system.svg and light.svg too. */

Try keyboard focus and your system’s high-contrast mode.

Translate the labels

Supply the group label and the three choice labels. With authored markup or custom choices, write your labels there instead. Logical CSS properties also support right-to-left layouts. 

<theme-switcher lang="fr"
  label="Thème"
  system-label="Appareil"
  light-label="Clair"
  dark-label="Sombre">
</theme-switcher>

<theme-switcher dir="rtl"
  label="Right-to-left layout">
</theme-switcher>

Add a reading palette

Custom choices include the three standard values. Your CSS handles the extra palette and its color-scheme. This example runs in a separate document: controls sharing a page should offer the same themes. 

<theme-switcher storage="none"
  label="Reading palette"
  choices='[
    {"label":"System","value":"system"},
    {"label":"Light","value":"light"},
    {"label":"Dark","value":"dark"},
    {"label":"Sepia","value":"sepia"}
  ]'>
</theme-switcher>

:root[data-theme='sepia'] {
  color-scheme: light;
  --page-background: #f6ecd6;
  --page-color: #493921;
}

Work with the preference

Use the JavaScript API without saving a choice

.value applies a preference and updates the other controls. storage="none" skips storage for this control; it doesn’t create an independent page theme. This button’s update won’t be saved by its peers either. 

<theme-switcher id="temporary" storage="none"
  label="Temporary preference">
</theme-switcher>

const control =
  document.querySelector('#temporary');
await control.ready;
control.value = 'system';

control.addEventListener(
  'theme-switcher:change', ({ detail }) => {
    console.log(detail.value,
      detail.resolvedTheme, detail.source);
  });
The API will be available after setup.

Back the preference with a cookie

LocalStorage works without configuration. Add cookie to save the preference in both places, so your server can use it too. A bare attribute shares the storage key; a value gives the cookie a separate name. On startup, a valid localStorage value wins, with the cookie as a fallback. storage="none" disables both. This isolated example uses its own key so its cookie settings don’t conflict with the other controls. 

<theme-switcher
  storage-key="theme-switcher-cookie-demo"
  cookie
  label="Saved site appearance">
</theme-switcher>

<!-- Or choose a different cookie name: -->
<theme-switcher
  storage-key="theme-switcher-cookie-demo"
  cookie="server-theme">
</theme-switcher>

Plan for loading and failure

Keep a native fallback

This frame deliberately doesn’t load the component. The radios remain usable, and the form still has a value to submit. Disable JavaScript and reload the whole demo to compare authored controls with generated ones. 

<theme-switcher>
  <fieldset>
    <legend>Color theme</legend>
    <label><input type="radio"
      name="theme" value="system"
      checked>System</label>
    <!-- Light and Dark radios too -->
  </fieldset>
</theme-switcher>

/* No loading-state CSS hides the inputs.
   No module means no page-theme behavior. */

Handle unavailable storage

A blocked storage API doesn’t stop the switcher from working. This isolated example simulates that restriction and displays the diagnostic. Configuration mistakes reject ready; storage errors don’t. 

control.addEventListener(
  'theme-switcher:error', ({ detail }) => {
    console.error(detail.phase, detail.error);
  });

// A storage error still allows:
await control.ready;
control.value = 'dark';

Apply a saved choice before first paint

For a saved preference to affect the first paint, restore it before your stylesheets load. Match the storage key and allowed themes to your control. The component then picks up that preference when it’s ready. Choose a theme in this frame, then use its reload link to try restoring it. The frame uses its own storage key. 

<script>
  try {
    const theme = localStorage.getItem(
      'theme-switcher-early-demo');
    if (['system', 'light', 'dark']
        .includes(theme)) {
      document.documentElement
        .setAttribute('data-theme', theme);
    }
  } catch (error) {
    console.warn('Theme storage unavailable.',
      error);
  }
</script>
<link rel="stylesheet" href="./styles.css">

<!-- In the body: -->
<theme-switcher
  storage-key="theme-switcher-early-demo"
  label="Saved appearance">
</theme-switcher>
