<theme-switcher>

A System, Light, and Dark picker built on <form-multi-switch>. See the README for installation and the API.

All controls on this page share its theme and use the demo-only storage key theme-switcher-demo, except the temporary control, which doesn’t save changes. Framed examples have their own page themes and storage settings.

Use Tab to reach a group, arrow keys to move between choices, and Space to select. Only System follows changes to your device’s color preference.

Use the generated control

Configure the control with attributes

Set a label; the component generates the three radios and their styles. It sets data-theme on <html>; the page’s CSS supplies the colors. Before JavaScript loads, this version has no controls. 

<theme-switcher
  label="Color theme"
  storage-key="theme-switcher-demo"
></theme-switcher>

/* Your page styles */
:root { color-scheme: light dark; }
:root[data-theme='light'] {
  color-scheme: light;
}
:root[data-theme='dark'] {
  color-scheme: dark;
}
body {
  background: Canvas;
  color: CanvasText;
}
Waiting for the component.

Reload to try restoring the saved choice.

Authored radios and form submission

Enhance an authored fieldset

The legend and labels name the controls, and the checked radio sets the reset default. The browser handles selection and form submission without JavaScript; the component adds page-theme changes. Authored markup takes precedence over the component’s choice, name, label, and value attributes. 

<form>
  <theme-switcher
    storage-key="theme-switcher-demo">
    <fieldset>
      <legend>Reading appearance</legend>
      <label><input type="radio"
        name="appearance" value="system"
        checked>Use my device</label>
      <label><input type="radio"
        name="appearance"
        value="light">Light</label>
      <label><input type="radio"
        name="appearance"
        value="dark">Dark</label>
    </fieldset>
  </theme-switcher>
  <button>Inspect FormData</button>
  <button type="reset">Reset</button>
</form>

Make it fit your site

Restyle the segments

Use the base component’s --multi-switch-* properties. Default styles live in a cascade layer, so your CSS can override them. 

<theme-switcher class="pill"
  label="Site appearance">
</theme-switcher>

.pill {
  --multi-switch-radius: 999px;
  --multi-switch-border: #173f63;
  --multi-switch-background: #eef4ff;
  --multi-switch-color: #173f63;
  --multi-switch-selected-background: #173f63;
  --multi-switch-selected-color: #fff;
}

Your CSS changes the control’s appearance, not the page palette.

Add icons without losing the labels

CSS masks add decorative icons. Keep text to name each radio; icon-only hides it visually, not from assistive technology. The hide-legend class below is author CSS, not a component attribute. The rule below hides the legend visually while keeping the group’s accessible name. 

<theme-switcher class="icons"
  label="Icons and text">
</theme-switcher>
<theme-switcher class="icons hide-legend" icon-only
  label="Icon-only appearance">
</theme-switcher>

.icons [data-multi-switch-choice]::before {
  content: '';
  inline-size: 1.25em;
  block-size: 1.25em;
  background: currentColor;
  mask: var(--theme-icon) center / contain
    no-repeat;
}
.icons [data-value='dark'] {
  --theme-icon: url('./dark.svg');
}
/* Add system.svg and light.svg too. */

theme-switcher.hide-legend legend {
  position: absolute;
  inline-size: 1px;
  block-size: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip-path: inset(50%);
  white-space: nowrap;
  border: 0;
}

Try keyboard focus and your system’s high-contrast mode.

Translate the labels

Supply translated group and choice labels; setting lang alone doesn’t translate them. The Arabic example inherits language and direction from its wrapper and uses the decorative icons above. Setting dir="rtl" on html works too; you don’t need to repeat it on the component. For custom choices or authored radios, translate their labels directly. 

<theme-switcher lang="fr"
  label="Thème"
  system-label="Appareil"
  light-label="Clair"
  dark-label="Sombre">
</theme-switcher>

<div lang="ar" dir="rtl">
  <theme-switcher class="icons"
    label="مظهر الموقع"
    system-label="النظام"
    light-label="فاتح"
    dark-label="داكن">
  </theme-switcher>
</div>

Add a reading palette

Include System, Light, and Dark when adding choices. Your CSS handles the extra palette and its color-scheme. This example runs in a separate document: controls sharing a page should offer the same themes. 

<theme-switcher storage="none"
  label="Reading palette"
  choices='[
    {"label":"System","value":"system"},
    {"label":"Light","value":"light"},
    {"label":"Dark","value":"dark"},
    {"label":"Sepia","value":"sepia"}
  ]'>
</theme-switcher>

:root[data-theme='sepia'] {
  color-scheme: light;
  --page-background: #f6ecd6;
  --page-color: #493921;
}

Work with the preference

Use the JavaScript API without saving a choice

.value applies a preference and updates the other controls. storage="none" skips storage for this control; it doesn’t create an independent page theme. This button’s update won’t be saved by its peers either. 

<theme-switcher id="temporary" storage="none"
  label="Temporary preference">
</theme-switcher>

const control =
  document.querySelector('#temporary');
await control.ready;
control.value = 'system';

control.addEventListener(
  'theme-switcher:change', ({ detail }) => {
    console.log(detail.value,
      detail.resolvedTheme, detail.source);
  });
The API will be available after setup.

Back the preference with a cookie

The component uses localStorage by default. Add cookie to save the preference in both places so your server can read it. On startup, a valid localStorage value wins, with the cookie as a fallback. A bare attribute uses the storage key as the cookie name; supply a value to name it separately. storage="none" disables both stores. 

<theme-switcher
  storage-key="theme-switcher-cookie-demo"
  cookie
  label="Saved site appearance">
</theme-switcher>

<!-- Or choose a different cookie name: -->
<theme-switcher
  storage-key="theme-switcher-cookie-demo"
  cookie="server-theme">
</theme-switcher>

Plan for loading and failure

Keep a native fallback

This frame doesn’t load the component. The radios remain usable, and the form still has a value to submit. Disable JavaScript and reload the whole demo to compare authored controls with generated ones. 

<theme-switcher>
  <fieldset>
    <legend>Color theme</legend>
    <label><input type="radio"
      name="theme" value="system"
      checked>System</label>
    <!-- Light and Dark radios too -->
  </fieldset>
</theme-switcher>

/* No loading-state CSS hides the inputs.
   No module means no page-theme behavior. */

Handle unavailable storage

A blocked storage API doesn’t stop the switcher from working. This isolated example simulates that restriction and displays the diagnostic. Configuration mistakes reject ready; storage errors don’t. 

control.addEventListener(
  'theme-switcher:error', ({ detail }) => {
    console.error(detail.phase, detail.error);
  });

// A storage error still allows:
await control.ready;
control.value = 'dark';

Apply a saved choice before first paint

Restore a saved preference before your stylesheets load to avoid a flash of the default theme. Match the storage key and allowed values to your control. Choose a theme in this frame, then use its reload link to try it. See the README for cookie restoration and Content Security Policy guidance. 

<script>
  try {
    const theme = localStorage.getItem(
      'theme-switcher-early-demo');
    if (['system', 'light', 'dark']
        .includes(theme)) {
      document.documentElement
        .setAttribute('data-theme', theme);
    }
  } catch (error) {
    console.warn('Theme storage unavailable.',
      error);
  }
</script>
<link rel="stylesheet" href="./styles.css">

<!-- In the body: -->
<theme-switcher
  storage-key="theme-switcher-early-demo"
  label="Saved appearance">
</theme-switcher>
